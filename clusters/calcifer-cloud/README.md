# calcifer-cloud

`calcifer-cloud` is the K3s cluster hosted on the remote VPS. Its Kubernetes resources are managed through Flux using a GitOps workflow.

## Flux

Flux is installed in the `flux-system` namespace and currently includes:

- source-controller
- kustomize-controller
- helm-controller
- notification-controller

The Flux `GitRepository` watches the `master` branch of `ssh://git@github.com/dmgiangi/calcifer` every minute. The `flux-system` Kustomization reconciles `./clusters/calcifer-cloud` every 10 minutes and prunes resources removed from Git.

Flux-generated manifests are stored in [`flux-system/`](flux-system/). The `gotk-components.yaml` and `gotk-sync.yaml` files are generated by Flux; avoid editing them manually unless the bootstrap configuration is intentionally being changed. The additional Flux reconciliation resources are kept in [`kustomizations/`](kustomizations/).

## TLS

cert-manager is installed through Helm and managed by Flux. The installation and configuration are separated under [`infrastructure/cert-manager/`](infrastructure/cert-manager/): the Helm chart and CRDs are installed first, then the Azure DNS credentials and Let's Encrypt `ClusterIssuer` resources are applied. The credentials are stored in an encrypted SOPS Secret.

The Azure DNS credentials and Let's Encrypt `ClusterIssuer` resources are ready for workloads that need certificates. Use the staging issuer while testing, then use `letsencrypt-production-azure` for production certificates.

## Adding workloads

Place cluster-specific manifests under this directory and include them from the relevant Kustomization. Commit and push changes to `master`; Flux will reconcile the cluster automatically.

Do not commit kubeconfig files, private keys, passwords, or other secrets.

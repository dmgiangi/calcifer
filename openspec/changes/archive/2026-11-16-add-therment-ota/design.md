# Design

## Context

Therment embeds Wi-Fi and MQTT credentials in its binaries. Home MQTT and HA are running; HA supports MQTT Update. The proposed two-slot layout is not active. A local hawkBit spike proved Management API basic authentication, target-token polling, assignment, artifact download and feedback, but not a production deployment. `calcifer-home` uses unencrypted `local-path` storage on a single node. Existing main `home-mqtt-broker` spec describes only an internal endpoint and predates the actual restricted LAN proxy; this pre-existing drift is not changed by OTA.

## Goals / Non-Goals

**Goals:** One simple Home-only update path with automatic polling, manual check, usable agent status, rollback, and practical recovery.

**Non-Goals:** New credential provisioning architecture, storage encryption, OAuth integration, fleet management, public access, or changing the current broker ACL policy.

## Decisions

1. **hawkBit on Home with `local-path`.** Reuse its DDI polling and Management APIs instead of writing a custom OTA server. Persist both database and artifacts, use a pinned image, restricted Kubernetes service and LAN-only TLS ingress. Configure DNS and the existing cert-manager issuer. Do not expose the route on Cloud; verify router, NAT, and actual external paths. Use a dedicated StorageClass/PV reclaim strategy that retains data on accidental claim deletion, with backups and a tested restore. The PVC and backups contain sensitive firmware and remain unencrypted at rest by the accepted decision; access and retention are restricted. A local hawkBit 1.0.3 test persisted a synthetic target across a restart with H2 file storage and `MODE=LEGACY`; without that H2 compatibility mode target creation failed. This does not establish production suitability or verify artifact backup. Confirm multipart temporary files and database cannot persist secrets in unintended paths.
2. **Basic authentication for upload; per-device target token for download.** Use separate identities and least-privilege hawkBit permissions. Flux deploys server credentials encrypted as SOPS Secret; the trusted workstation uses a SOPS-encrypted credential with an authorized age key. Feed secrets via protected input, not arguments, logs or shell history. The device token is provisioned with the first USB firmware and treated as secret; document rotation and recovery. Validate TLS and hostname for every path, including clock synchronization. Do not assume LAN alone restricts network access. OAuth is deferred.
3. **Explicit publication, automatic check.** A local script builds on the trusted machine, uploads an immutable unique version, assigns to `therment-01`, sends a non-retained MQTT check request, then watches hawkBit until a matching final action or timeout. If MQTT is unavailable the polling path remains a fallback and the script reports the trigger failure; retrying must not create conflicting versions/actions. Restrict logs and temporary files. Use SOPS credentials for hawkBit and a separate authorized MQTT identity; document their lifecycle.
4. **Minimal HA and agent interface.** Therment publishes retained MQTT Update discovery and state under `homeassistant/update/therment-01-ota/config` and `therment/therment-01/ota/state`, with existing availability. A non-retained `therment/therment-01/ota/set` command requests an immediate check, never a URL. Rate limit and coalesce commands; the current broker has no ACLs and plain MQTT does not authenticate the source of a message. Optionally harden ACLs only after inventory and non-disruptive verification. HA exposes the Install button and diagnostic outcome; output from the deploy/status script includes stable JSON with device, release, action, phase, outcome and timestamps. Device feedback is the source for success; availability and action IDs prevent stale retained state from being mistaken for success.
5. **Two-slot update and local confirmation.** HTTPS endpoint and release metadata are trusted only after certificate and hostname validation; ensure DDI artifact URLs are fixed to the expected private origin and reject redirects to other origins. Check size, SHA-256 and image validity before activating; a checksum alone is not an independent signature. For this first version accept reliance on trusted server, private transport and controlled release publication; signed images can be a later improvement. Prevent concurrent updates, wait until both relays are off before restart, enforce timeout/backoff, and keep regulation autonomous during download. On boot de-energize relays and preserve compressor-delay protection. Enable ESP-IDF rollback; confirm after local relay initialization, settings availability and controller loop startup, without requiring Wi-Fi/MQTT. On explicit sensor error remain fail-safe; do not equate lack of network with firmware failure. Confirm only after successful initialization; use watchdog/bounded checks and report rollback on reconnect.
6. **USB first, no automatic flash.** Inspect actual flash size, partitions and current bootloader; securely back up and prove recovery of NVS and current firmware, verify image fits and physical relay states. Then install bootloader, OTA partition table and initial image via a documented maintenance-window procedure. A first slot has no known-good OTA fallback until a second working image exists; retain USB recovery. Avoid full erase unless restoration is verified. Do not activate until hardware checks are complete.
7. **Always-available manual check.** The installed Home Assistant rejects `update.install` when installed and latest versions match. Keep the MQTT Update entity for installation and progress, and publish a separate diagnostic MQTT button that sends the same non-retained check request even when no update is currently advertised. The device still accepts only authenticated hawkBit assignments.

## Risks / Trade-offs

- [Unencrypted PVC and binaries] → isolate server and backup access; prohibit Git/CI publication and control retention. This does not protect against stolen disks/backups.
- [Plain MQTT trigger] → no URL or credentials in messages; rate limit, idempotency and trusted authenticated HTTPS; validate the network path and revisit ACLs without disrupting existing clients.
- [Home-only endpoint] → configure DNS, certificate and trusted root; verify external paths and reject DNS/TLS failures. No disabled certificate checks.
- [Failed boot or compressor operation] → safe output initialization, inactive slot, rollback and delayed compressor; physical reset behavior and power loss require hardware tests.
- [Loss of state or ambiguous release] → persistent hawkBit database and artifacts, backups, idempotent unique release/action IDs and explicit unknown outcomes after timeout.
- [Version-specific hawkBit behavior] → verify exact pinned image, minimum API permissions, artifact location, download URLs and TLS before rollout.
